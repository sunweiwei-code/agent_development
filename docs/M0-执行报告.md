## 3. 切分与抽取方法

```
content_list.json
  → 噪音过滤（按内容，不按类型）
  → 以「地点」为锚点切分（45/45 实验室均有该字段）
  → 联系方式按 bbox 横向中心重归属
  → 字段抽取（地点/负责人/研究方向/基本介绍/主要成果/联系方式/组别）
```

**锚点选择依据**：实测各结构标记出现次数 —— `地点 45`、`负责人 45`、`基本介绍 45`、`研究方向 46`、`主要成果 43`。`地点` 与实验室数完全对齐，作锚点最稳；不依赖标题层级（有 3 个实验室名被 MinerU 标成 level 2，用 `text_level` 切分会漏）。

## 5. 四个技术坑（已修）

| # | 坑 | 修前 | 修后 |
|---|----|------|------|
| 1 | MinerU 把页脚位置的真实正文标成 `footer`/`page_footnote`，按类型一刀切会丢联系方式 | contact **4.4%（2/45）** | 改为按内容过滤噪声，**77.8%** |
| 2 | 页脚块排在该页正文之后，联系方式归属整体错位一格（RoboMaster 的 QQ 群被给了 ACM） | L01 无联系方式、L02 拿到 L01 的群号 | 按 bbox 横向中心就近归属（左栏 x≈350 / 右栏 x≈600），**归属正确** |
| 3 | 联系方式正则 `^手机` 误杀正文「**手机**应用开发、游戏开发…」 | research_areas 97.8% | 收紧为「标签+冒号」或纯邮箱，**100%** |
| 4 | 清洗时做 NFKC，把中文全角标点全转半角 | 展示与 diff 出现「研究机构,实验室」 | NFKC 只用于比对层；存储层改为「两 CJK 字符之间的半角标点」定向转全角 + 括号配平，地址 `C1-201,205` 不受影响 |

**前三条共同点**：都是「过滤规则比数据更粗」。预防方式：任何白/黑名单过滤都要先抽样验证**命中侧**与**误杀侧**，不能只看命中。

**第 4 条是另一类错误**：把 PRD 8.2 的「比对规范化」当成「入库清洗」用了。比较层与存储层的规则必须分开——比较层可以激进归一（为了判等），存储层要保留原文形态（为了展示与溯源）。
